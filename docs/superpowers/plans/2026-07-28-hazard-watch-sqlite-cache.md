# Hazard Watch SQLite Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `get_hazard_watch`'s live EPA query (which occasionally exceeds its timeout and returns a 500) with a local SQLite cache, populated by a manually-run sync script.

**Architecture:** A new sync script (`sync_hazard_watch.py`) fetches PBT-flagged TRI releases for all 50 states + DC from EPA and writes them into a new SQLite database (`hazard_watch_cache.db`), which is committed to the repo. `get_hazard_watch` is rewritten to query that local database instead of calling EPA live — same response shape, zero network dependency at request time.

**Tech Stack:** Python 3.9, stdlib `sqlite3` (no new dependency). No frontend changes.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-hazard-watch-sqlite-cache.md` — read it before starting if anything below is unclear.
- **No functionality change.** `get_hazard_watch`'s response shape (list of `{facility_id, facility_name, chemical, chem_id, year, total_release}` objects, sorted by `total_release` descending) must stay byte-identical to today — neither `HazardWatchPage.tsx` (Classic) nor `HazardWatchPageNew.tsx` (New Design) need any changes.
- **Scoped to Hazard Watch only.** Do not touch TRI Facility Search (`get_facilities_by_state`) or Site Search (`site_search`) — different endpoints, different EPA data sources, no timeout history, explicitly out of scope.
- The sync script is run manually (not scheduled/automated) — matching TRI's genuinely annual update cadence.
- The resulting `hazard_watch_cache.db` file is committed to the repo so the feature works immediately, with no manual sync step required before first use.

- [ ] **Step 1: Create the sync script**

Create `sync_hazard_watch.py`:

```python
"""
Populates hazard_watch_cache.db with PBT-flagged TRI releases for every
US state + DC, sourced from EPA's live Envirofacts API. Run this manually
(python3 sync_hazard_watch.py) whenever EPA publishes new TRI data --
roughly annually. Safe to re-run: each state's rows are replaced, not
duplicated. Tolerates individual state failures (logs and continues) so
one bad EPA response doesn't abort the whole sync -- just re-run the
script afterward to retry whichever states failed.
"""
import sqlite3
import time

import httpx

from main import PBT_CHEMICAL_IDS

DB_PATH = "hazard_watch_cache.db"

STATES = [
    "AL", "AK", "AZ", "AR", "CA", "CO", "CT", "DE", "DC", "FL", "GA", "HI",
    "ID", "IL", "IN", "IA", "KS", "KY", "LA", "ME", "MD", "MA", "MI", "MN",
    "MS", "MO", "MT", "NE", "NV", "NH", "NJ", "NM", "NY", "NC", "ND", "OH",
    "OK", "OR", "PA", "RI", "SC", "SD", "TN", "TX", "UT", "VT", "VA", "WA",
    "WV", "WI", "WY",
]


def _fetch_state(state_abbr):
    url = (
        f"https://data.epa.gov/dmapservice/tri.tri_facility"
        f"/state_abbr/equals/{state_abbr}"
        f"/join/tri.tri_reporting_form"
        f"/tri.tri_facility.tri_facility_id/equals/tri.tri_reporting_form.tri_facility_id"
        f"/join/tri.tri_form_totals"
        f"/tri.tri_reporting_form.doc_ctrl_num/equals/tri.tri_form_totals.doc_ctrl_num"
        f"/sort/tri.tri_reporting_form.reporting_year:desc"
        f"/1:1000/json"
    )
    with httpx.Client(timeout=60.0, follow_redirects=True) as client:
        r = client.get(url)
        return r.json()


def _init_db(conn):
    conn.execute(
        """
        CREATE TABLE IF NOT EXISTS hazard_watch (
            state_abbr TEXT NOT NULL,
            facility_id TEXT,
            facility_name TEXT,
            chemical TEXT,
            chem_id TEXT,
            year INTEGER,
            total_release REAL
        )
        """
    )
    conn.execute(
        "CREATE INDEX IF NOT EXISTS idx_hazard_watch_state ON hazard_watch(state_abbr)"
    )
    conn.commit()


def sync_state(conn, state_abbr):
    rows = _fetch_state(state_abbr)
    flagged = [
        (
            state_abbr,
            row.get("tri_facility_id"),
            row.get("facility_name"),
            row.get("cas_chem_name"),
            row.get("tri_chem_id"),
            row.get("reporting_year"),
            (row.get("total_air_release") or 0)
            + (row.get("total_water_release") or 0)
            + (row.get("total_land_release") or 0),
        )
        for row in rows
        if row.get("tri_chem_id") in PBT_CHEMICAL_IDS
    ]
    conn.execute("DELETE FROM hazard_watch WHERE state_abbr = ?", (state_abbr,))
    conn.executemany(
        """
        INSERT INTO hazard_watch
            (state_abbr, facility_id, facility_name, chemical, chem_id, year, total_release)
        VALUES (?, ?, ?, ?, ?, ?, ?)
        """,
        flagged,
    )
    conn.commit()
    return len(flagged)


def main():
    conn = sqlite3.connect(DB_PATH)
    _init_db(conn)

    succeeded = []
    failed = []
    for state_abbr in STATES:
        try:
            count = sync_state(conn, state_abbr)
            succeeded.append(state_abbr)
            print(f"{state_abbr}: {count} flagged rows")
        except Exception as exc:
            failed.append(state_abbr)
            print(f"{state_abbr}: FAILED ({exc})")
        time.sleep(0.5)

    conn.close()
    print(f"\nDone. {len(succeeded)} succeeded, {len(failed)} failed.")
    if failed:
        print(f"Failed states (re-run this script to retry): {', '.join(failed)}")


if __name__ == "__main__":
    main()
```

- [ ] **Step 4: Replace `get_hazard_watch`'s implementation**

In `main.py`, replace the existing `get_hazard_watch` function (currently doing a live `httpx` call and in-Python PBT filtering) with:

```python
"""
Hazard Watch endpoint
Every release in a state involving an EPA-designated PBT chemical, worst
offenders first. Backed by a local SQLite cache (hazard_watch_cache.db,
populated by sync_hazard_watch.py) rather than a live EPA query -- the
underlying live query (a 3-way join across tri_facility/tri_reporting_form/
tri_form_totals) is expensive enough that it occasionally exceeded this
endpoint's timeout for larger result sets, and since TRI data itself only
updates annually, a periodically-refreshed local cache is a better fit
than tolerating EPA's live query latency on every request.
"""
@app.get("/api/state/{state_abbr}/hazard-watch")
async def get_hazard_watch(state_abbr: str):
    conn = sqlite3.connect(HAZARD_WATCH_DB_PATH)
    try:
        cursor = conn.execute(
            """
            SELECT facility_id, facility_name, chemical, chem_id, year, total_release
            FROM hazard_watch
            WHERE state_abbr = ?
            ORDER BY total_release DESC
            """,
            (state_abbr,),
        )
        rows = cursor.fetchall()
    finally:
        conn.close()

    return [
        {
            "facility_id": row[0],
            "facility_name": row[1],
            "chemical": row[2],
            "chem_id": row[3],
            "year": row[4],
            "total_release": row[5],
        }
        for row in rows
    ]
```

This completely replaces the function's body — no more `httpx.AsyncClient`, no more in-Python `PBT_CHEMICAL_IDS` filtering (that filtering now happens once, in `sync_hazard_watch.py`, at sync time — not on every request).
